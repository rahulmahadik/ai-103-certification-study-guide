The five skill areas

weights exactly as published; each sub-skill condensed to one line
1

Plan and manage an Azure AI solution

25–30%

Choose services

  • Match the task to an LLM, small language model, multimodal model or Foundry Tool
  • Pick services for generation, grounding, vector search and agent workflows
  • Choose how to retrieve and index; choose memory, tool and knowledge integrations

Set up in Foundry

  • Design the infrastructure and choose deployment options
  • Configure model and agent deployments
  • Wire projects into CI/CD pipelines

Manage and secure

  • Quotas, scaling, rate limits and cost
  • Performance, drift, safety events, grounding quality
  • Ingestion quality, index health, relevance
  • Managed identity, private networking, keyless credentials, role policies

Responsible AI

  • Safety filters, guardrails, risk detection, moderation
  • Evaluators, safety evaluations, explanation tooling
  • Trace logging, provenance, approval workflows
  • Oversight modes, constraints, tool-access controls
2

Implement generative AI and agentic solutions

30–35%

Generative apps

  • Deploy and use large, small, code and multimodal models
  • Build retrieval-augmented generation into an app
  • Design tool-augmented flows and multistep reasoning pipelines
  • Evaluate for hallucination, groundedness, relevance and safety
  • Integrate through Foundry SDKs and connectors; connect an app to a project

Agents

  • Define roles, goals, conversation tracking and tool schemas
  • Combine retrieval, function calling and conversation memory
  • Plug in APIs, knowledge stores, search and content understanding
  • Orchestrate several agents together
  • Run flows with little or no supervision, behind approval controls
  • Monitor agents, judge their behaviour, analyse the failures

Optimize and operate

  • Tune with prompt engineering and model parameters
  • Reflection, chain-of-thought evaluation, self-critique loops
  • Tracing, token analytics, safety signals, latency breakdowns
  • Orchestrate several models, flows, or an LLM with a rules engine
3

Implement computer vision solutions

10–15%

Generate and edit

  • Make images and video from text prompts and reference media
  • Inpainting, mask-based edits, prompt-driven changes
  • Edit generated video; image generation controls are size, quality and count (n) — there is no seed

Multimodal understanding

  • Read visual context; short or detailed captions, one image or many
  • Answer questions using only what the image actually shows
  • Alt text and longer descriptions that meet accessibility guidelines
  • Content Understanding for visual characteristics; per-segment video analysis
  • Single-task and pro-mode pipelines; locate objects and regions

Responsible AI

  • Filter unsafe or disallowed images
  • Catch instructions hidden as text inside an image
  • Enforce watermarks, banned symbols and brand rules
4

Implement text analysis solutions

10–15%

Language model text analysis

  • Pull out entities, topics, summaries and structured JSON
  • Detect sentiment, tone, safety issues and sensitive content
  • Translate with Azure Translator or a language model
  • Shape the output for a specific domain — compliance summaries, clinical notes, contract clauses

Speech

  • Speech to text and text to speech inside an agent conversation
  • Speech as an agent modality, including custom speech models
  • Reason straight from the audio rather than a transcript
  • Translate speech with language models and Foundry Tools
Prebuilt or model. A prebuilt Azure Language capability gives a fixed, versioned label set at a predictable price per text record. A language model copes with categories and output shapes the prebuilt ones simply do not have.
5

Implement information extraction solutions

10–15%

Retrieval and grounding

  • Ingest and index documents, images, audio and video
  • Set up semantic, hybrid and vector search for grounding
  • Enrich with custom or built-in skills for text, images and layout
  • Configure RAG ingestion, including OCR over documents
  • Connect retrieval pipelines to workflows and agent tools

Extract from documents

  • Pipelines that combine OCR, layout analysis and field extraction — on v4.0 the general document model is gone (layout returns key-value pairs if you ask for them) and business card is deprecated; both still appear in older question banks
  • Content Understanding turns mixed documents, images and audio into structured output an agent can cite
  • Analyzers that return structured or markdown output
Schema first. Field names, types and which ones are required, decided before you build. The schema is the contract with whatever consumes the output.
Standard or pro. Standard reads one file and pulls the fields out. Pro reasons over several inputs at once and can weigh them against reference data — for judgement, not for reading.

How Foundry is organised

Old wording vs new. A project on a Foundry resource is the current architecture. A hub-based project is the older classic one, and the exam likes to contrast the two.

How RAG works

Hybrid is the recommended mode for generative AI applications. Reach for RAG when the model needs private or fast-changing knowledge, or the answer depends on events after its training cutoff.

Prompt, RAG or fine-tune

Three fine-tuning techniques. SFT trains on labelled prompt-and-answer pairs. RFT uses a grader to reward better answers. DPO learns from preferred versus rejected pairs. Training data is JSONL, one conversation per line.

Services and syntax

deployment types, endpoint shapes, the four built-in tools and the prompt patterns

Deployment types

TypeScope, billing and fit
Global StandardAny region. Pay-per-token, highest quota. The default
Global ProvisionedAny region. Reserved PTUs, predictable throughput
Global BatchAny region. Async jobs, 24-hour target turnaround with no SLA, 50% cheaper
Data Zone
Std / Prov / Batch		One data zone. The same three, held inside a US, EU or APAC zone
Standard
Regional Provisioned		Single region. Regional residency rules, or low volume
DeveloperAny region, no residency or SLA guarantee. Fine-tuned model evaluation only, fixed 24-hour lifetime
Default answer. Global Standard, unless the scenario names a data-residency rule, a guaranteed-throughput requirement, a large asynchronous batch job, or evaluating a fine-tuned model.
Quota and throttling. Quota is TPM (tokens per minute) and RPM (requests per minute), set per model, per region, per subscription. Over the limit returns 429 — retry with backoff, raise the quota, or move to provisioned throughput for guaranteed capacity.

Four tools you must know

ToolWhat it adds
code_interpreterSandboxed Python. No network access
web_searchCurrent public web facts, fetched as it answers
file_searchYour uploaded files, through a vector store
functionYour own code, when the model asks for it
Who runs what. The model decides when to use a tool. With function it only asks — your application runs the code and hands back a function_call_output.
One store or many. file_search grounds one set of documents. An enterprise agent spanning many stores uses Foundry IQ instead. These four are the ones the module covers — the Responses API supports more.
Memory and knowledge. A conversation holds history server-side, so later turns read it without you resending. Knowledge is what grounds the answer — a vector store for one document set, Foundry IQ across many.

Prompt engineering

Persona
Give the model a role and the answer becomes audience-aware
Format template
Fix the output shape so it is easy to parse
Chain of thought
Ask for the reasoning. Non-reasoning models only
Few-shot
Zero, one or several worked examples in the prompt
Delimiters
Split instruction from content with ---, Markdown or XML tags
Temperature or top_p. Temperature and top_p both control randomness — turn one, not both. Low for factual work, higher for creative.
Recency bias. Words near the end of a prompt carry more weight, so repeat the key instruction there when it keeps getting ignored.

Evaluation and responsible AI

named metrics, named principles, named layers — these are memorisation marks

Evaluation metrics

FamilyMetrics, and when they fit
Generation quality
AI-assisted		Groundedness (Pro is a yes-or-no verdict), relevance, coherence, fluency. Needs a GPT model as the judge
Risk and safetySelf-harm, hateful and unfair, violent, sexual, protected material, indirect attack. Reported as a defect rate at or above a severity threshold, usually Medium
NLP metrics
pure maths		F1, BLEU, METEOR, ROUGE, GLEU. No judge model needed; they generally need ground truth
Agent behaviour
pass / fail		Intent resolution — did it understand the ask. Task adherence — did it stay inside its instructions. Tool call accuracy and tool output utilization — right tool, right arguments, and did it use the result
You rarely write an evaluator. The built-in library covers quality, RAG, safety and agents. Write a custom one only for a domain rule none of them cover.
Pick by output shape. Open-ended writing with no single right answer takes AI-assisted metrics. A reference answer exists takes NLP metrics — and ROUGE leans on recall, which is why it suits summarization.
Higher or lower is better. Quality index, F1, GTPS: higher is better. ASR, cost, latency, TTFT: lower is better. A higher WMDP just means the model knows more that could be dangerous.

Principles, stages and layers

Fairness Reliability & safety Privacy & security Inclusiveness Transparency Accountability
Red teaming is how you verify: testers deliberately try to make the system produce harmful output before release. Measuring means a baseline — prompts likely to trigger each harm, run and scored against strict criteria, so you can tell later whether a fix actually helped.

Mitigate: four layers, model outward

LayerWhat you change
1 · ModelPick a model matched to the job, or fine-tune on your own data
2 · Safety systemContent filters and prompt shields
3 · System message and groundingBehaviour instructions, prompt engineering, RAG from trusted sources
4 · User experienceConstrain the UI, validate in and out, be honest about limitations

Content filters and shields

Content filter: 4 harm categories × 4 severity levels

Safe
Low
Medium
High
Hate and fairness
Sexual
Violence
Self-harm
Safe is never blocked. It is annotated and is not configurable. You set a threshold per category — off, low, medium or high — separately for prompts and for completions, and it flags that severity and above.
Task adherence is a fifth guardrail category, and it is about agents rather than harm: it catches an agent drifting off its instructions — a misaligned tool call, or a reply that does not match what the user asked for.
Prompt shields sit alongside the filters and catch systematic abuse, such as someone trying to talk the system out of its own system prompt.

The vocabulary Microsoft keeps renaming

32 terms, one line each, in the names the exam uses today

Platform

Microsoft Foundry
The platform for AI development on Azure: a portal plus an SDK.
Foundry resource
The Azure resource that supplies compute, storage and tools to projects.
Project
Holds the connections, data, code and assets for one solution. Belongs to one resource.
Hub-based project
The older classic architecture. New work uses a project on a Foundry resource.
Foundry Tools
Prebuilt APIs and models: Language, Speech, Translator, Document Intelligence, Content Understanding. Once called Azure AI Services, before that Cognitive Services.
Foundry IQ
One knowledge base over many knowledge sources; an agent reaches it over MCP. Not an Azure AI Search knowledge store, which is enriched skillset output in Azure Storage.
MCP
Model Context Protocol — how custom and third-party tools plug into a project.
Agent
A named configuration of a model, its instructions and its tools.

Models and deployment

LLM / SLM
Large: deep reasoning, long context, most compute. Small: cheap and fast, runs on modest hardware and edge devices.
Reasoning model
Works a problem step by step internally. Maths, code, science, strategy.
Embedding model
Turns text into vectors. Powers semantic search and RAG.
Multimodal model
Takes text plus images or audio and answers in words.
Model card
Provider, capabilities, benchmarks, responsible-AI notes, deployment options.
PTU
Provisioned throughput unit — reserved capacity instead of pay-per-token.
Deployment name
What you pass in the model parameter to route a request.

Building and grounding

Responses API
Stateful. Chains turns with previous_response_id; read response.output_text. Recommended for new work.
ChatCompletions API
Stateless list of messages. Resend the history each turn; read choices[0].message.content.
DefaultAzureCredential
Entra ID identity-based authentication. The production choice over keys.
Streaming
stream=True returns output as it is produced, so the interface never looks frozen.
Vector store
Indexed, chunked file content that file_search queries.
Grounding
Giving the model real facts to answer from instead of letting it guess.
Cosine similarity
The angle between two vectors. Near 1 means close in meaning.
Context window
Everything sent on one request: instructions, history, tool schemas, tool output, retrieved text.

Tuning, evaluation and safety

Zero / one / few-shot
No examples, one example, several examples in the prompt.
Recency bias
Text near the end of a prompt carries more weight.
Distillation
Fine-tune a small model on a large one's output for similar quality at lower cost.
Drift
Two senses. After fine-tuning: over-specialising until general performance degrades. In monitoring: a deployed model’s behaviour shifting from its baseline over time.
Conversation
Server-side chat history an agent reads on later turns.
Defect rate
The share of responses at or above a severity threshold, usually Medium.
Groundedness
Whether the answer is based on the supplied context. Groundedness Pro is a yes-or-no verdict.
Prompt shields
Abuse detection for systematic misuse and attempts to override the system prompt.
Transparency note
Microsoft's own documentation of a service's known limitations.
